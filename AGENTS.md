# AGENTS.md

Context for coding agents working on QWatch OSS: an Expo / React Native
companion app that talks to QWatch Pro smart bands directly over BLE. Start
with [README.md](README.md), then [docs/APP.md](docs/APP.md) (architecture,
background mode, alerts, upload, UI kit) and
[docs/PROTOCOL.md](docs/PROTOCOL.md) (the band's BLE protocol).

## Commands

Use Bun: `bun run <script>` for scripts and `bunx <tool>` for one-off tools.

```bash
bun run typecheck && bun run lint && bun run format:check   # run before finishing
bun run format                                              # oxfmt (no Prettier)
```

### Android release build

`android/` and `ios/` are generated by `expo prebuild` and gitignored. Never
edit them by hand except for throwaway experiments; put native code in
`modules/` or a config plugin, and settings in `app.json`.

```bash
bunx expo prebuild --platform android          # after app.json, icon or native dep changes
cd android
ANDROID_HOME=$HOME/Android/Sdk JAVA_HOME=/usr/lib/jvm/java-17-openjdk \
  ./gradlew assembleRelease -PreactNativeArchitectures=arm64-v8a
adb install -r app/build/outputs/apk/release/app-release.apk
./gradlew --stop                               # don't leave daemons running
```

- Release builds are signed with the debug key.
- `adb install` can hang until the phone is unlocked and the Play Protect
  prompt is accepted.
- After upgrading a native dependency (e.g. `react-native-worklets`), stale
  CMake caches can fail the build with "missing and no known rule to make
  it". Delete that library's `android/.cxx` and `android/build`, and those of
  the libraries that link against it, under `node_modules`.

## Versioning

Bump the patch version for every release build, in **both** `app.json`
(`expo.version`) and `package.json`, then run prebuild so Android's
`versionName` follows. The Settings tab shows it via
`Constants.expoConfig.version`.

## Architecture notes

- **State:** `src/lib/store/` holds a small synchronous store; every `set`
  notifies all subscribers immediately.
- **BLE:** `src/lib/ble/client.ts` (`qwatch`) owns scanning, connecting, the
  handshake, polling and reconnects. Protocol frames, commands and decoders
  live in `src/lib/protocol/`.
- **Startup:** the uploader, alerts and background wiring start once per JS
  runtime at module scope in `src/app/_layout.tsx`, **not** in an effect.
  Android unmounts the React tree when the activity is destroyed (swiped from
  recents) while the foreground service keeps the runtime and BLE link alive.
- **Background (Android):** `modules/qwatch-background` provides a
  `connectedDevice` foreground service (notification only) and a coarse
  main-looper tick.
  - React Native pauses JS timers in the background, so background work must
    be driven by that tick or by BLE notifications, never `setTimeout` or
    `setInterval`.
  - Android 12+ only lets the service start while the app is visible.
- **iOS:** there is no native module; BLE notifications wake the app.

## Power budget

Background power draw must stay negligible: about 0.05–0.15 s of CPU per minute
with the app backgrounded or swiped away, and the main thread close to idle.

- No wake locks, alarms, or polling loops in the background.
- Use LowPower BLE connection priority in the background.
- Keep `react-native-worklets` ≥ 0.10.4. Earlier versions never pause the UI
  runtime's 60 Hz frame loop in the background, which costs ~3 s of CPU per
  minute.
- To measure, read `/proc/<pid>/stat` (utime + stime) and the main thread's
  `voluntary_ctxt_switches` over 60 s. For call stacks, temporarily add
  `<profileable android:shell="true"/>` to the generated manifest and use
  `simpleperf record --app <package>`, then prebuild again to remove it.

## Code conventions

- **Lint:** oxlint with custom anti-slop rules in `tools/oxlint/`. In
  particular:
  - every type assertion needs a `// SAFETY:` comment;
  - no `unknown` parameters or returns;
  - no conditional empty-object spreads (`...(x ? {...} : {})`);
  - use `satisfies Record<...>` rather than widening an object's type;
  - no `parseInt` / `parseFloat`; use `Number`.
- **Styling:** Uniwind (Tailwind) classes. Merge them with `cn` and build
  variants with `tailwind-variants`. Colours and hard shadows come from the
  theme in `src/global.css`.
- **UI:** primitives live in `src/components/ui/`.
  - The custom `Text` accepts no `style` prop; wrap it in a `View` to position
    it.
  - Animations use Reanimated 4 and the Material 3 Expressive spring tokens in
    `src/lib/motion.ts`.
- **Comments:** keep the existing density. Explain why, not what.

## Don't

- Don't commit the vendor APK or any decompiled vendor code. Document protocol
  findings in `docs/PROTOCOL.md` in your own words.
- Don't market or describe the app as a medical device.
